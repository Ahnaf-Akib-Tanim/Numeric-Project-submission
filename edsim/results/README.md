# `results/` — everything the scripts produce

Nothing in this folder is written by hand. Every file here is generated by a script in
`../scripts/`, and every file can be traced back to the exact command that produced it.

## Start here

| File | What it is |
|---|---|
| **`RESULTS_SUMMARY.md`** | The headline digest — master comparison table, the paper-vs-ours deviation table, the verdict under three objectives, and the significance matrix. Written by `run_08_final_comparison.py`. Read this first. |
| **`PROVENANCE.md`** | Append-only log. One entry per script execution: the exact command, the timestamp, the wall-clock time, the key settings and numbers, and every file it wrote. Read this to answer "where did this number come from?". |

## Folders

### `tables/`

Each table exists twice:

- `<name>.csv` — machine-readable, with a four-line provenance header:
  ```
  # produced by: scripts/run_01_validate_paper.py
  # command    : python scripts/run_01_validate_paper.py --reps 100 --seed 20250402
  # timestamp  : 2026-08-28 21:14:07
  # args       : {"reps": 100, "seed": 20250402, "workers": 14, ...}
  ```
  (skip these lines when loading, e.g. `pd.read_csv(path, comment="#")`)
- `<name>.md` — the same table as Markdown, ready to paste into the report, with the
  provenance line as a footnote.

Naming: `wp1_*` = validation, `wp2_grid_*` = the paper's grid search, `wp2_*` = the c·μ
policies, `wp3_*` = Nelder-Mead, `wp4_*` = staffing, `wp5_*` = common random numbers,
`sens_*` = sensitivity, `final_*` = the consolidated comparison.

### `figures/`

Each figure exists twice: `<name>.png` at 200 dpi for the slides, and `<name>.pdf` as
vector output for the report. Colours, markers and line styles are fixed per policy across
every figure — see `../src/plotting.py`.

### `raw/`

| File | Contents |
|---|---|
| `<script>.manifest.json` | Machine-readable record of one script execution: command, args, environment (Python and library versions), elapsed time, key numbers, every output path, and the full contents of every table it wrote. |
| `wp1_replications.csv` | One row per (policy, replication) from the validation run — all KPIs, so any aggregate in `tables/` can be recomputed independently. |
| `final_replications.csv` | The same for the final six-policy comparison. |
| `wp2_grid_surface.json` | The coarse grid's response surface: `k1s`, `k2s`, and the objective / mean wait / SL₄ matrices. Used by `run_04` to draw the simplex trajectory on the surface the lattice had to evaluate in full. |
| `wp3_grid_budget.json` | How many lattice points and week-long simulations the brute-force search consumed. This is the baseline WP3's speed-up is measured against. |
| `wp3_nelder_mead_optimum.json` | The tuned `(k1, k2)`. Read by `run_05` and `run_08`; if it is missing, those scripts fall back to the paper's published thresholds and say so in their output. |
| `full_pipeline_console.log` | Complete terminal transcript of the last `run_all.py`. |

## Regenerating

```bash
cd ..
python scripts/run_all.py              # everything, ~35-50 min
python scripts/run_01_validate_paper.py   # or any single script
```

Re-running a script overwrites its own outputs and appends a fresh entry to
`PROVENANCE.md`, so the log accumulates history while the artefacts stay current.

Results are deterministic given `--seed` (default `20250402`) and `--reps`. Two runs with
the same flags produce byte-identical tables. Changing either changes the numbers, which is
why both are recorded in every provenance header.
